# P16.3 — English learning content (bilingual plan, scenarios, quiz and practice feedback)

Audits U1 and journey #9: in the English UI the learning content stayed Arabic and misaligned (plan titles
flushed to the far side of their checkbox, quiz question right-aligned with left-aligned options, Arabic
scenarios, push-back lines, feedback bullets, value names, exit reply and admin detail).

## What

- **Data.** `data/ours/content_en.csv` (135 rows, `key,text_en,source`): authored English for the four plan
  goals, 16 activity titles, 6 scenario situations and suggested responses, 6 customer push-back lines,
  18 reply options and their fixed feedback, 36 checklist sentences shown to the trainee (`done_ar`,
  `add_ar`), the 5 quiz questions with their 15 options, and the fixed `scenario_end`, `plan` and `quiz`
  replies. Keyed by ids (`customer:S01`, `option:S01-O2`, …), so the Arabic files can be reworded by
  others without a conflict here. Value names use the official English `company_value`. The official CSVs
  are untouched; Arabic stays the reference.
- **Server (additive).** `app/content_en.py` loads the file once and fills optional `*_en` fields:
  `Activity.title_en`, `Milestone.learning_goal_en`, `ScenarioOut.scenario_en`, `Option.text_en`,
  `QuizItem.question_en` + `options_en` (both or neither), `Proposal.titles_en`, `DetailActivity.title_en`,
  `Feedback.strengths_en / improve_en / suggested_good_response_en / customer_en`, and `Reply.text_en` on
  `scenario_end`, `plan` and `quiz`. Feedback English is matched sentence by sentence to the checklist or
  option row it came from (in `tools.give_scenario_feedback`, after `to_schema`), so the feedback logic in
  `app/scenarios.py` is unchanged and a reworded or deduplicated sentence leaves the list Arabic rather
  than half translated. `tip_ar` (model-written) and K-rows (cited verbatim) are never translated.
- **Contract.** `app/schemas.py`, `web/src/api/types.ts`, 13 fixtures (placeholder Arabic texts replaced by
  the real `data/ours` texts so each English line is the translation of the Arabic beside it),
  `contracts/fixtures/INDEX.md`, `docs/api_contract.md` §6i, `tests/test_contract.py`.
- **Web.** `components/ui/ContentText.tsx` (`pickContent`, `useContent`, `contentProps`, `ContentText`,
  `ArabicOnlyTag`): the English UI shows `*_en` when sent, else the Arabic with `lang="ar" dir="rtl"`; the
  Arabic UI never shows English. Inline titles are `<bdi>` isolates inside a line that keeps the UI
  direction, so a fallback Arabic title stays beside its checkbox. Used on the plan (titles, goals), progress
  next-up, Day 90 summary, first-day card, quiz (question and options share one language and direction),
  scenario list and chat cards (situation, options, push-back line, strengths, add-this, suggested reply),
  the in-chat plan/quiz cards, the progress proposal, the typed exit reply and the admin intern detail
  (milestone names and activity titles). `ValueLabel` shows the English value name alone in the English UI.
  The model's tip keeps its Arabic text with one small "Arabic only" tag; the quiz explanation K-row gets
  "Source text in Arabic". A picked option's user bubble repeats the option as shown. i18n block
  `contentEn` at the end of `ar.ts` / `en.ts`.

Not changed: router, agent, guards, factcheck, feedback logic, state, Toast, TracePanel, the admin timeline,
KbTable, ChatScreen layout, MentorRequestsPanel, CheckScreen. The chat practice bar's value name (from
`ChatScreen`) and mentor-request activity titles stay Arabic (out of this task's files).

## Tests

- `tests/test_content_en.py` (145): file format; every shown Arabic item has an English row and no row is
  orphaned; English has no Arabic letters, contact or link and adds no number the Arabic lacks; option
  feedback names an official value; plan/quiz/scenario/feedback/proposal/fixed replies carry the English
  through the tools and the HTTP API, Arabic unchanged, no `tip_en`; a non-fixed sentence leaves the list
  Arabic.
- `tests/test_contract.py`: the English fields are optional (fixtures validate without them), named in
  `types.ts`, and keep their alignment rules.
- `web/src/components/ui/__tests__/contentEn.test.tsx` (11): English plan title beside its checkbox and
  English goal; Arabic fallback as an isolated RTL `<bdi>` in an unflipped line; Arabic UI unchanged; quiz
  question and options in one language and direction (English, or both RTL Arabic); scenario list in
  English with the English value; feedback in English with exactly one "Arabic only" tag on the model tip;
  old feedback without English stays RTL Arabic; `ValueLabel` per language.
- `chat.test.tsx`: the English-UI practice tests now expect the authored English push-back and suggested reply.

Visual check (own offline server on port 8070, Playwright, English UI, 360 and 1280): plan, quiz, scenarios,
progress, chat start/feedback and admin detail show no Arabic learning text and no horizontal scroll; the
Arabic UI plan is unchanged.

## Integrator

No key needed; nothing to run in the main folder for this item. LLM feedback in English mode shows the
English fixed sentences plus the Arabic model tip with its tag.
