# P16.1: routing, practice and Rumour Check fixes from the journey audit

Audit items 1, 3, 4, 5, 6, 8(a–e), 10, plus U7 and journey #14 (Rumour Check).

- Practice starts only on an explicit request (#1). These start practice: a short practice message, a chip
  («تدريب: …», "Practice: …"), a practise verb («خليني أتدرب», "let me practise", "practising") or a request
  verb before a practice noun («بدي تدريب»). A first-person track claim with a situation cue («أنا موظف مبيعات
  وعميل…», jury T06/T07 and dev D126–D131) also starts practice, unless it is a yes/no or entitlement question
  («أنا موظف مبيعات، هل يحق للزبون…»). A message that only mentions a customer goes to the answer path
  («شو بعمل إذا الزبون مش موجود…», «هل يحق للزبون إرجاع المنتج؟», "Can a customer return…").
- Own track (#1, #3): the e5 match runs only over the intern's track (`TurnState.role` = `ChatRequest.role`;
  the role reaches the router, never the answer path). A first-person claim in the text sets the track, and
  naming both tracks allows either (RT19/RT20 unchanged). The agent refuses a model `start_scenario` from another
  track (`scenario_other_track`) and any model `start_scenario` the router did not see as practice
  (`router_not_practice`). A refused choice is never cached. "practise/practising" was added to the practice
  patterns.
- A new question during practice (#1) leaves practice and gets an answer (`leave_practice` → state cleared).
  The message must start with a question word (or «بدي إجازة…»), name a topic about the employee (leave, hours,
  showrooms, manager, policy, wholesale…) and contain no second-person word (`عندك`, `بدك`, a `ـك` suffix, "you").
  If any of these is unclear, the message stays practice feedback («كم فرد بالعيلة؟» is still feedback).
- First day (#5): a model `show_plan` no longer replaces a knowledge question the router sees when retrieval has
  a candidate row (band `answer` or `not_confirmed`) and no milestone is named. So «شو لازم أعمل أول يوم دوام؟»
  gets K12, and «شو الخطة المقترحة إلي لأول 90 يوم؟» still gets the plan.
- Pay (#6): a pay question with no employment decision in it («كم راتبي خلال فترة التجربة؟», «متى بنقبض
  الراتب؟») gets the out-of-scope refusal ("not in the approved knowledge base, ask HR") with no row attached.
  The employment guard still fires (trace `employment: pay:…`), so the model never sees the message. A raise,
  promotion, confirmation, firing or probation outcome keeps the employment card. Dev rows D023, D085 and D119
  were relabelled from `guard_employment` to `refuse` to match this behaviour.
- Exit reply (#10): «سؤال ثاني» / "another question" → «انتهى التدريب على هذا الموقف. تفضّل، اسأل سؤالك.». The
  English UI, or a message written in English, also gets a fixed English line in `text_en` for both exits. The
  web `scenario_end` bubble now shows `text_en`.
- Feedback (#8):
  - (a) one value per scenario: option and model values no longer replace the scenario's value.
  - (b) customer lines rewritten so they no longer assume what the trainee said (no apology, no questions, no
    promise to come back). They still pass the small-talk checks.
  - (c) a model tip that repeats a checklist line is dropped (`tip_repeats_checklist`).
  - (d) a model tip that names a fact the scenario, checklist and reply never mention (delay, damage, mismatch,
    return, discount, warranty, appliance, family) is dropped (`tip_off_scenario`). The cache stores the reply
    with the dropped tip set to `null`, so an unverified tip is never cached.
  - (e) a deterministic promise check («أكيد فيها», «بوعدك», «بتوصل الساعة…», "I promise", "definitely has"; not
    after a negation) adds the integrity line «انتبه للنزاهة: …» to "improve" in any scenario, offline and model.
    A «confirmed information only» checklist item is never listed as a strength in that case.
- Rumour Check: the contact guard counts only when the claim holds or asks for a phone number, email or link
  (#4), so «…للمدير على الواتساب» is checked against K16. Pay claims are still guarded. Claims also split on an
  ASCII comma (not inside a number) and between two clauses joined by «وإن / وأن / و إن» or English "and" (U7;
  user substrings, 5-claim cap). English units (showroom(s), day(s); a year after "in / since / year") count for
  the number rule, so "The number of showrooms is 20." → `differs` 20 vs 17 (#14).
