# P16.2 — progress reaches the server, honest quiz line, one "question" definition, toast placement

Journey audit items 2, 12, 13, 17 and UI/UX audit items I1, I2.

- #2 (HIGH) Practice and quiz completions are persisted. `progress.fromProposal` (chat practice
  feedback, quiz finish, chat-confirmed progress) now sends `PUT /api/progress` for the plan ids it
  newly ticks, like a Plan tick. Chosen over ticking on the server in `/chat` and `/quiz/check`: the
  client already decides which activity a scenario or the quiz completes, the endpoint and its
  validation exist, and the server routes stay unchanged. Unknown ids are not sent (one would make the
  server reject the whole update). Reload (server wins) and the admin list/detail now show the same %.
- #13 The server stores quiz answers per question (admin counts only, no intern read route), so no
  server result is shown. Instead: signed in, the Progress intro says progress is saved on the server
  and quiz results in this browser; a ticked quiz activity without a local attempt reads
  «أُنجز — تفاصيل المحاولة على الجهاز الذي استخدمته» instead of «لم تُجرَ محاولة بعد».
- #12 Admin detail: «سأل المساعد» log events use the same definition as the question count
  (`QUESTION_TOOLS`). Practice replies already show as «تدرّب على موقف»; greetings, plan and quiz
  turns are not questions. No contract change.
- #17 / I1 Toasts moved from under the header to the bottom end, above the phone bottom bar and the
  screen's sticky dock (`useToastDock`: chat composer, quiz actions; CSS var `--da-toast-dock`), so they
  never cover the page H1 or the composer. The chat keeps a new reply above a visible toast
  (`toastsTop`), so the progress toast never covers the newest message.
- I2 Un-ticking an activity shows a neutral «أُلغي التحديد: التقدم {pct}%», not «تم تحديث التقدم».
- i18n: new `progressSync` block (ar/en) at the end of the dictionaries.
- Tests: practice and quiz completions send the PUT, reload keeps the ticks, PUT ticks match
  `/api/progress` and the admin list/detail %, log chat events = question count, quiz-elsewhere line
  and server intro, untick toast, toast placement and dock var, chat scroll keeps the reply above the toast.
