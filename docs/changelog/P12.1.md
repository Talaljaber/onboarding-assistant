# P12.1 — import documents into the knowledge base (reviewed passages)

- **Flow.** In the admin «قاعدة المعرفة» screen, «استيراد مستند» (`#/admin/kb/import`) uploads a document;
  the review screen (`#/admin/kb/import/<id>`) lists its passages in document order (page, topic, keywords,
  suggested question) to edit, discard/restore, approve one by one or select and approve together. An
  approved passage becomes an added K-row through `KnowledgeBase.add_many` (next free ids in draft order,
  history `editor`, one reindex for the batch, the same 423 lock as the editor) and is cited verbatim. The
  review screen links each new K id to the editor (`#/kb?row=K19` opens that row). **Nothing from a file is
  answerable before approval.** KB reset removes those rows like any added row and puts their drafts back to
  `draft` (`row_id` null) so they can be approved again.
- **Extraction (stdlib only).** `.txt`/`.md` (UTF-8, BOM ok; form feed = new page; markdown headings, bullets,
  links), `.csv` (one passage per row; known columns `answer_ar`/`text`, `topic`, `keyword_en`, `source_page`),
  `.docx` (zip + ElementTree over `word/document.xml`; heading styles / outline level; `w:br type=page`,
  `pageBreakBefore` and `lastRenderedPageBreak` advance the page, counted once), `.pdf` only when `pypdf` is
  importable (`requirements.txt` has it as a commented optional line; the capabilities endpoint reports
  `pdf`). Rejected: other types, empty/non-UTF-8/binary text, docx over 20 MB unpacked or 2000 entries,
  a DOCTYPE/ENTITY in the XML, more than 200 passages, files over 2 MB. The file bytes are never stored.
- **Chunker (deterministic).** Drops bare page numbers, dot-leader TOC lines, short copyright lines and short
  lines repeated on 3+ pages (numbers masked only for lines ≤ 40 chars); headings start a new passage and are
  the topic hint, never part of the text; paragraphs ≤ 600 chars stay whole and a passage < 120 chars absorbs
  the next paragraph of the same heading and page; longer paragraphs split at `. ! ? ؟ ۔` and line breaks,
  packed to ~450 (hard 600); only a single sentence over 600 is cut at a space. Passages never cross a
  heading or a page.
- **Optional model step.** «التنظيم بالذكاء الاصطناعي» is off by default, enabled only in LLM mode, and warns
  that the passages are sent to the AI model (approved documents only). `prompts/organize_v1.md` on the pinned
  answer model (temperature 0, JSON, ≤ 20 passages per call, 15 s per call, 45 s total, the budget module).
  The model proposes topic / keyword_en / question_ar / keep / order / merge_with and never passage text.
  `verify_organize` rejects the whole reply for unknown or repeated ids or a bad shape, and each value on its
  own (contact/link/K-id/numbers not in that passage, lengths, Arabic in keywords, a question without Arabic,
  order not a permutation, merges not between same-page neighbours within 600 chars). Rejected values keep
  the offline labels (topic from the nearest heading or «General», keywords from frequent Latin words). A
  reply is cached only when every value passed. Logs carry counts only.
- **`question_ar`** is shown in review only and stored on the draft; the KB has no retrieval-hint field, so it
  is not added to the row (row text stays the document's text).
- **API (admin only).** `GET /api/admin/kb/import/capabilities`, `POST/GET /api/admin/kb/imports`,
  `GET /api/admin/kb/imports/{id}`, `PATCH /api/admin/kb/drafts/{id}`, `POST /api/admin/kb/imports/{id}/approve`.
  The upload is JSON with base64; the 32 KB body limit is raised to 3 MB only for that route and only with a
  valid admin token (checked before the body is read). New error code `imports_unavailable` (503) when the
  store cannot hold imports. Contract: schemas, `types.ts`, 8 fixtures + `error_503.json`, `api_contract.md` §6c.
- **Data.** `supabase/migrations/0003_kb_imports.sql` (`kb_imports`, `kb_drafts`; RLS on, no policies, browser
  roles revoked; not applied here). LocalStore creates the same tables on open. Import calls never flip the
  SupabaseStore to local: a missing table only disables import (503); chat and the KB keep using Supabase.
- **Tests.** `tests/test_kb_import.py` (43: extraction per type incl. a hand-built PDF and the no-pypdf path,
  chunker rules, offline labels, organize verifier and cache rule with a scripted fake client, batching and
  merges, API admin-only/body limit/errors/approve → cited verbatim/reset/drafts/423/503/LLM-mode organize,
  both stores incl. Supabase without the migration); contract tests; web tests for the form, the review list
  and the client calls. The e2e storyboard is unchanged (it passed from a temporary copy on port 8036).
