# P21.2: the final report and comparison view

Owner: "how would I evaluate and differentiate between like 10 interns at the end of the internship period … the
final report will have what they accomplished, the progress they made … that he submitted all his tasks on time or
which one was overdue". Owner chose both a side-by-side table and a printable page per intern. Integrator's rule:
**no automatic ranking, no composite score, no "best" label** — the system gathers evidence, the mentor decides.

- API: `GET /api/admin/report[?track=Sales|Delivery]` (admin only) → `FinalReport {generated_at, interns, label_ar}`,
  every ACTIVE intern in roster order. `FinalReportRow` = intern id and names, track, `started_at` (first recorded
  activity, else the day added), `plan_percent`, `activities_done/total`, `tasks` (the P21.1 `TaskSummary`),
  `checkpoints` (the P20 `DetailCheckpoint` entries: first answers only), `scenarios_practised`,
  `quiz_questions_answered`, `questions_sent_to_mentor` (null when unreadable), `last_active`. Built from the same
  helpers as the interns list and detail (`interns.report_row` over `summary_row`, `mentor_requests.task_summary`,
  `api.intern_checkpoints` now taking a context read once per request). No new storage, no migration.
- `InternDetail` adds `started_at` and `questions_sent` (what the printable page needed); the page's task list reads
  the existing `GET /api/admin/requests?intern_id=`.
- Checkpoint fix: `QuizSetSummary.my_result {answered, first_attempt_right, total} | null` — the signed-in intern's
  own result for a checkpoint set, with the admin's first-answer rule (null for practice sets, the official quiz,
  no profile). The quiz runner uses it instead of the browser-memory stop-gap (`dada.v1.checkpoint.*` in
  localStorage is gone); with `my_result` missing it falls back to this visit's first run as before.
- Contract: `schemas.py` (`FinalReport`, `FinalReportRow`, `FINAL_REPORT_NOTE_AR`, `CheckpointMyResult`, the two
  `InternDetail` fields, `my_result` with a checkpoint-only validator), `types.ts` (+ `isFinalReport`), `client.ts`
  (`getFinalReport`), fixtures `final_report.json` (new), `intern_detail.json`, `quiz_sets.json`, INDEX.md,
  `docs/api_contract.md` §6n. The no-score contract test now also scans the report shapes with the same allow-list
  (`first_attempt_right` inside `checkpoints` only) and bans ranking words (rank, position, best, top, overall,
  composite, percentile, winner).
- Web: «التقرير النهائي» / "Final report" button on the admin Interns screen → `#/admin/report` (under the Interns
  tab, no new nav item): the fixed note, the fictional-examples line, a track filter (All · Sales · Delivery, asks
  the server), a sortable table from 1024 px (name · track · plan % with activities · tasks on time / late / overdue /
  open · one column per checkpoint quiz "1 / 2", «لم يبدأ», or "—" when not in it · scenarios · practice questions ·
  questions sent · last active) and one full card per intern below that with a sort control. No default sort, no
  rank numbers, nothing highlighted. Per intern `#/admin/interns/:id/report` (linked from the comparison and the
  intern page): header with both names, track and dates, plan completion with activity dates, tasks with deadline,
  done time and the P21.1 timing badge, checkpoint results, practice counts, questions sent, and an empty
  «ملاحظات المشرف» box; «طباعة» prints it on A4 (`@page` in index.css; the shell and toolbar are hidden; rows do not
  split across pages). Both languages, RTL; no sideways scroll at 360/390/768/1280; 44 px targets on phones.
- Privacy: `docs/privacy_ai_note.md` §8 (the intern sees their own shared result) and §9 (what the report shows, no
  ranking, no new storage).
- Tests: `tests/test_final_report.py` (admin only, active interns only, roster order, track filter and a bad track,
  plan / tasks / checkpoints / counts equal the list and detail, practice and official answers never shared, retries
  never move it, no score or rank key; `my_result` equals the admin's result, retries keep it, another intern sees
  only their own, anonymous gets the official quiz only); `tests/test_contract.py` (`test_final_report_contract`, the
  extended no-score scan). Web: `components/report/__tests__/report.test.tsx` (note, list order, no default sort,
  checkpoint cells, task counts, header sort, track filter request, phone cards, intern page with tasks / timing /
  checkpoints / counts / notes / print, English, failed task list, entry links), `QuizList.test.tsx` (my_result:
  earlier visit, partly answered, re-read after a first attempt, nothing in localStorage), `App.routes.test.tsx`.
