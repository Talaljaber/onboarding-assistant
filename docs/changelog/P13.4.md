# P13.4: model title detection for PDF and text imports

- PDF and `.txt` files carry no heading styles, so sections ran together. With «organize» ticked and the
  server in LLM mode, the import now sends the extracted lines (numbered across the document, with their page,
  ≤ 200 lines per call, lines cut to 160 characters in the prompt) to the pinned model with the new
  `prompts/titles_v1.md`. The model returns only `{"title_lines": [int, ...]}`; it never outputs text.
  Runs before chunking (`app/kb_import/titles.py`, `app/llm/paths.py:llm_titles`).
- Verifier `app/verify.py:verify_titles`: the reply must be an object with exactly `title_lines`, a list of
  integers (else the whole reply is rejected: `bad_shape` / `invalid_json`). Each number must name a line of
  that call, appear once, and the line must be ≤ 80 characters, contain a letter, not be the document's last
  line, and not be over 40 characters while ending in sentence punctuation (. ! ? ؟ ۔ : ؛ ;). A failing number
  is dropped and counted; the reply is cached only when nothing was dropped (verify-before-cache, cache hits
  re-verified), as for organize.
- Rebuild: chosen lines become heading blocks; the other lines stay in their original paragraph, cut at each
  title and at each page; a rule-based heading the model did not choose joins the text after it. Every
  character is kept and in order (tested). A batch that fails (error, timeout, rejected reply, budget, the
  20 s title deadline, more than 10 batches) keeps the rule-based headings for its lines; when no batch
  succeeded the extracted blocks are used unchanged. Title time comes out of the existing 45 s organize
  deadline (organize gets what is left).
- Which files: `pdf` and `txt`; also a `.docx` in which Word marked no heading at all (typed with bold text);
  never `md` or `csv`, nor a `.docx` that has headings (`reason: "structured"`).
- API (additive): `OrganizeSummary.titles` = `TitlesSummary {used, count, reason}` (optional field, always set
  on upload). Contract triplet updated: `app/schemas.py`, `web/src/api/types.ts`, `contracts/fixtures/
  import_detail.json` + `INDEX.md`, `docs/api_contract.md`.
- Web: the review screen shows «عناوين الأقسام التي حدّدها النموذج: N.» / "Section titles detected by the
  model: N." when the model ran; the AI option's help text mentions title detection (the release warning is
  unchanged: the same passages' text is what leaves the laptop).
- `extract.pdf_page_blocks` factored out of `_pdf_blocks` (no behaviour change) so the eval can apply the PDF
  page rules to plain text.
- `scripts/eval_titles.py`: four fixed fictional documents (Arabic and English, PDF-like layout) scored for the
  rule-based headings and the model's titles (tp / fp / fn, passages). Dry run without a key or with
  OFFLINE=1 (model columns `not_run`, exit 0; `--require-llm` → exit 2); probe failure → 3; budget below
  `--min-budget` → 4. Not run here (no key in the worktree). Dry-run baseline: rule_tp=9 rule_fp=2 rule_fn=3.
- Privacy: `docs/privacy_ai_note.md` lists what the title step sends (document lines with number and page,
  only with the tick, only in AI mode) and the limitation below.
- Limitation: a title line over 40 characters with no closing punctuation is joined to the next line by the
  PDF wrap rule before the model sees it, so it cannot be picked.
- Tests (`tests/test_kb_import.py`): verifier (good, bad shape, out of range, too long, long sentence, no
  letter, last line, duplicates), prompt contents, cache only when clean, rebuild (verbatim, pages,
  paragraphs), service path (used, fallback on failure, skipped for md/csv/docx with headings, not requested,
  LLM off, docx without headings), batching with global numbers and a failed second batch, a PDF page split
  by colon-ended titles, an API test that turns one run-on page into one passage per section, and the eval
  script (dry run, fake model).
