# P10.3 — Plan ticks reach the manager view

**Bug.** Ticking an activity on the Plan or Progress screen was saved in the browser only. The server
learned about progress only from the chat confirm card, so the admin's manager view showed 0% for
employees who had ticked activities on the Plan screen.

**Fix.**
- New `PUT /api/progress` `{profile_id, activity_ids, completed}` → `ProgressResponse`. Ids must be
  activities of the profile's role plan (400 otherwise, 404 unknown profile). Idempotent; `completed:
  false` unticks.
- The web client sends every tick, untick and progress reset in the background, plus ticks made before
  the profile existed. The browser copy stays the employee's source of truth: a failed save changes
  nothing on screen.
- Contract: `ProgressUpdate` in `app/schemas.py` and `web/src/api/types.ts`, fixture
  `progress_update_request.json`, `docs/api_contract.md`, `INDEX.md`.

**Tests.** `tests/test_api.py::test_plan_ticks_reach_the_manager_view` (tick, idempotent, untick,
manager row, wrong-role id, empty list, bad and unknown profile); `useAppState.test.tsx` checks the
requests the web client sends.
