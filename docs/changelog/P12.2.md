# P12.2 — human small talk; facts stay cited

- Router (`app/router.py`): `detect_small_talk_intent` names seven intents, offline and in normalised form:
  `greeting`, `how_are_you`, `thanks`, `goodbye`, `identity`, `ack` (ok / تمام / 👍 / laughter) and `unclear`
  (a lone «?» / «؟» / «...», a single emoji, ≤ 2 letters, one vowel-less Latin token). Arabic incl. Jordanian
  dialect, English and a little Arabizi. A cue counts only in a short message (≤ 8 words) with no topic word
  (leave, salary, values, branch, founded, …) and, once cues and filler words are removed, at most two words
  (none after an ack) with no question word or «?» left: «hi, when was the group founded?» stays a knowledge
  question. Route order unchanged (guards, practice, plan, quiz first). The router tool stays `greet` (no
  contract change); `args.intent` replaces `args.kind`.
- Replies (`app/smalltalk.py`): offline pool of 2–4 short Arabic/English pairs per intent; the first greeting
  of a thread (no `last_user_message`) mentions practice and sources, later ones stay short. The pick is a
  CRC of the normalised message plus a per-profile turn counter, so repeated «hello»s vary.
- LLM mode: router small talk skips the tool-choice call. One call of the pinned answer model with
  `prompts/smalltalk_v1.md` (temperature 0, JSON, 200 tokens, ≤ 2 s). Input: the message, the intent, a style
  word (plain / upbeat / curious, picked by the same seed) and the first-turn flag; never the role, a name,
  the profile, KB rows or earlier messages. Variety at temperature 0 comes from the style word (each
  (message, intent, style, first) reply is cacheable). Output `{"text_ar", "text_en"}`.
- Verifier `verify_small_talk` (`app/verify.py`): exact shape; both non-empty and ≤ 220 chars; no digits or
  number words (`numbers_in` + English number words); no contact/link; no K-id or KB document name; no person
  after an honorific; no prompt/injection echo; no policy noun (leave, salary, probation, contract, دوام,
  إجازة, راتب, تجربة, …); Arabic letters only in `text_ar`, English in `text_en`. Rejected, timed out,
  offline, or an injection-looking message → the pool. Cached only after it passed; a hit is re-verified.
- Contract use: `kind: "text"`, `text_ar` always the Arabic reply; `text_en` set only when the person wrote
  English (or wrote no letters in the English UI). Arabizi gets Arabic. `fixed_english` and its greeting /
  thanks lines are removed (no other fixed text used them).
- Trace: `router:greet`, `small_talk:<intent>`, then `llm`, `cache:small_talk` or `pool`
  (+ `small_talk_fallback:<reason>`). Mode is `llm` only when the model text was used.
- Web: a `text` reply shows `text_en` alone (ltr, `lang="en"`) when set, else the Arabic alone; no mode,
  cached or lock chip on text replies; no "fixed English line" note. Suggested chips unchanged.
- `scripts/eval_smalltalk.py` (integrator only, LLM mode): 21 small-talk messages and 10 greeting-prefixed DEV
  questions → `results/smalltalk_dev.csv` + summary line; refuses with OFFLINE=1 or no key, stops below
  USD 0.5 left. Not run here (no key in the worktree).
- Tests: `tests/test_smalltalk.py` (intents both ways, pool through the verifier, variety, language, verifier
  rejections, LLM path with a fake client, never-cached-when-unverified, prompt content, «?» → clarify, DEV
  greet rows, eval script guard); web chat tests for one-language rendering. DEV offline 106/154 unchanged
  (no row changed kind, ids or verdict); red team offline 19/20 unchanged.
