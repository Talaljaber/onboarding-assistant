# P11.1 — verified English helper translation of answers

- Contract: `ChatRequest.lang` (`"ar"` default | `"en"`); fixtures, `INDEX.md`, `api_contract.md` and
  `types.ts` updated. `Reply.text_en` (already in the frozen contract) is now filled. No trace schema
  change: one new step per English-UI answer (`translate:ok`, `cache:translate`, `translate:off`,
  `translate:fixed`, `translate:<reason>`).
- Server: after the answer tool, `app/translate.py` translates an `answer` reply (not the `not_confirmed`
  band, not refusals, guards, scenarios, plan or quiz) when `lang == "en"` and the LLM is available.
  One call of the pinned answer model with `prompts/translate_v1.md` (temperature 0, JSON object,
  600 tokens, own 2.5 s deadline after the answer is ready; budget and hard-failure rules as for the
  other paths). Input: the verified Arabic answer (fixed partial note removed) and the cited rows'
  Arabic text; never the question, ids, document names, role or profile.
- Cache key = model + `translate_v1:translate-v1:<file hash>` + the rendered prompt (exact Arabic input)
  + params, so an edited row or answer gets a new translation; a hit is re-verified before use.
- Verifier `verify_translation` (`app/verify.py`): strict `{"text_en"}` shape; non-empty; ≤ 3× the
  Arabic length (min 120, max 2400 chars); no contact/link (`has_contact_or_link`); every number,
  digits or English number words, must be in the Arabic answer or cited rows (`foreign_numbers`,
  percent check); no K-id not in the Arabic; no document name except the cited rows'; no person after
  an honorific unless the Arabic has one; Arabic letters ≤ 10% of letters. Rejections are logged by
  reason only (`verifier_rejection`, `translation`), never with text.
- Web: the chat and the KB try-it panel send the UI language; English mode shows `text_en` above the
  Arabic, a muted "available in AI mode" / "no checked translation" line when it is null, a fixed
  English line under the fixed partial note, the not-confirmed text and the fixed refusals (Arabic
  kept), and a translation line in the trace panel. New `chatEn.*` keys in `ar.ts`/`en.ts`.
- `scripts/eval_translation.py` (integrator only, LLM mode, DEV answers only) writes
  `results/translation_dev.csv` and a summary line; refuses with OFFLINE=1, without a key or with
  less than USD 0.5 budget left. Not run here (no key in the worktree).
- Tests: `tests/test_translation.py` (verifier, cache, chat turn, eval guard); web chat and trace
  panel tests.
