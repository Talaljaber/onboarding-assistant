# P18.1: questions inbox (consent-based)

- Intern: on a Rumour Check claim labelled `not_found` or `related`, «أرسلها لمشرفي» / "Send to my mentor"; in chat,
  under a non-guard refusal (`out_of_scope`) or the not-confirmed band, «أرسل السؤال لمشرفك؟» with «أرسله» / «لا،
  شكراً». Both open one confirm sheet with exactly the text that will be sent (the claim or the user's question,
  editable, ≤ 600) and the privacy line; nothing is stored before Send. Never offered on guarded turns (employment,
  contact, injection, or a refusal whose trace shows a guard hit, e.g. a pay question); the server refuses them
  too. A question already sent shows «أُرسل إلى مشرفك» instead of the prompt.
- «أسئلتك لمشرفك» in the chat dock beside «من مشرفك» (`components/questions/MyQuestionsPanel.tsx`): collapsed bar,
  titled «أجاب مشرفك عن سؤالك» once one is answered; each answered question quotes the answer row verbatim (K-id)
  with «أعد السؤال», which asks it again in chat (the new row is cited). Read on mount and on window focus.
- Admin: «أسئلة المتدربين» / "Interns' questions" (`#/admin/questions`, nav item with the open count): filters
  open / answered / closed / all, newest first with intern, source, time and text; «أجب» opens the answer dialog
  (answer, topic and keyword pre-filled from the nearest live row, optional source name) and toasts «أُضيف إلى قاعدة
  المعرفة: K19»; «أغلق دون جواب» dismisses.
- API (contract triplet; fixtures `question_create_request.json`, `question.json`, `questions.json`,
  `admin_questions.json`, `question_answer_request.json`, `question_answered.json`, `question_dismissed.json`;
  `docs/api_contract.md` §6j): `POST /api/questions` (scoped by the session profile id like requests; guards +
  `verify.injection_suspected` → 400 `field: text`; `verify.has_contact_or_link` → 400), `GET /api/questions?profile_id=`,
  `GET /api/admin/questions?status=`, `POST /api/admin/questions/{id}/answer` (the KB editor's add path, now the
  shared `api.kb_add_row`: same `KbNewRow` validation, next K id with status `added`, re-index, version bump; contact
  rule on every field; default document «Mentor answer», page 1), `POST /api/admin/questions/{id}/dismiss`. Answer
  and dismiss only from `open` (400 `field: status`). Store failures → 503 `requests_unavailable` (no new error code).
- Data: `supabase/migrations/0006_questions.sql` (`mentor_questions`, cascade on interns, RLS on, no policies,
  revoked from anon/authenticated, idempotent) and the same table in `LocalStore` (`QUESTIONS_SCHEMA`). Supabase
  never flips to local for this table; its update is guarded with `status=eq.open`.
- Privacy: "Chat text is not stored, except a question you choose to send to your mentor" in the sheet, About and
  `docs/privacy_ai_note.md` (§4 table + paragraph).
- Tests: `tests/test_questions.py` (consent: nothing stored by chat or check; guards, contact, limits; scoping and
  deactivated intern; 401s; answer → K19 `added`, version bump, row verbatim to the intern, re-ask cites K19; once
  only; dismiss and filters; 503; both stores incl. Supabase over `httpx.MockTransport` and no migration 0006),
  `tests/test_contract.py::test_questions_inbox_contract`, `web/src/components/questions/__tests__/questions.test.tsx`.
- Integrator: apply `0006_questions.sql`; build `web/dist`. P18.2 can wire `mailer.question_submitted` into
  `question_add` and `mailer.question_answered` into `admin_question_answer` in `app/api.py`.
