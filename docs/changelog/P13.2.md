# P13.2 — mentor requests ("learn this / do this / read this")

Text-only requests from the admin (the mentor) to interns. No files or attachments, no replies or
threads, no event history: one row per request and intern.

- Data: `supabase/migrations/0004_mentor_requests.sql` adds `mentor_requests` (id, intern_id, title ≤ 120,
  note ≤ 1000, kind learn|do|read, kb_id, activity_id, due_date, status new|in_progress|done, created_at,
  updated_at, status_changed_at) with the 0002/0003 security pattern (RLS on, no policies, nothing granted
  to `anon`/`authenticated`). `LocalStore` creates the same table (SQLite). Both stores implement
  `mentor_requests`, `mentor_requests_create`, `mentor_request_update`, `mentor_request_delete`; like the
  import tables, a failing call (e.g. Supabase without 0004) never flips the store and the API answers
  503 `requests_unavailable`.
- API: admin `GET/POST /api/admin/requests`, `PATCH/DELETE /api/admin/requests/{id}`; a new request goes
  to one intern (`intern_id`) or every active intern of a track (`track`, one row each). Intern
  `GET /api/requests?profile_id=` and `PATCH /api/requests/{id}` `{profile_id, status}`: scoped by the
  intern-session profile id (any profile of an active intern, like progress); another intern's request
  is a plain 404. Links are ids checked server-side (`kb_id` against the live KB, `activity_id` against
  the plan of the target's track); the response carries the K-row verbatim (`kb_row: Source`) and the
  activity title so the intern opens either in one click.
- Safety: `title` and `note` go through `verify.has_contact_or_link` (the verifier's email / link /
  phone rule) and are refused with 400 and a `field`. Request text never reaches chat, prompts or turn
  logs (only `app/api.py` and `app/mentor_requests.py` touch it). Status is a to-do marker, never a score.
- Contract: `app/schemas.py` (`MentorRequest*`, `RequestCounts`, `LinkedActivity`, error code
  `requests_unavailable`), `web/src/api/types.ts` (types + guards), eight fixtures, `INDEX.md`,
  `docs/api_contract.md` §6d, `tests/test_contract.py`.
- Web: "From your mentor / من مشرفك" panel at the top of the assistant (intern home) with an open-count
  badge, cards (kind, title, note, suggested date, K-row toggle showing the verbatim row, activity link
  to the plan) and a three-state status control with optimistic update and an error toast that puts the
  status back. Admin intern page: a requests section (status per request, edit, delete with confirm) and
  a "New request" dialog (kind, title, note, K-row picker, plan-activity picker, date, this intern or the
  whole track). Admin interns list: a compact counts-by-status overview. Arabic and English keys under
  `mentorReq`.
- Tests: `tests/test_mentor_requests.py` (fan-out, links, limits, contact rule, admin-only, intern scope,
  503), store round trips for both stores in `tests/test_store.py` (Supabase via `httpx.MockTransport`,
  incl. a missing table that must not flip), contract checks; web `components/requests/__tests__`.
- Integrator: apply `supabase/migrations/0004_mentor_requests.sql` (after 0003), then rebuild `web/dist`.
