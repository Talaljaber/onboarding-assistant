# P21.1: task deadlines and reminder emails

Owner: "in the tasks page can we add a deadline for the task the admin requests and it sends a reminder email 10
mins before the deadline to the intern … and in the final report we will have that he submitted all his tasks on
time or which one was overdue". The final report is a later task; this one stores and serves the data.

- Data: migration `supabase/migrations/0010_request_deadlines.sql` (**the integrator applies it**, idempotent):
  `mentor_requests.due_at`, `done_at`, `reminder_sent_at` (timestamptz, null); backfill `due_at` = 23:59
  Asia/Amman of `due_date`, `done_at` = `status_changed_at` for requests already done; a partial index for the
  reminder check; `mail_log_event_check` re-created with every earlier event plus `request_reminder`. LocalStore:
  the same columns in the schema, added (with the same backfill) on open to an older SQLite file.
- Rules (`app/deadlines.py`, shared by both stores, the views and the reminder thread): Asia/Amman is a fixed
  UTC+03:00 (Jordan has no daylight saving since 2022; Windows Pythons have no tz database). One `due_date`
  rule: a sent `due_at` decides and `due_date` becomes its Amman day; only `due_date` sent → `due_at` = 23:59
  Amman that day; null in the deciding field clears both. Moving to done sets `done_at`, leaving done clears it;
  a new deadline clears `reminder_sent_at` (the same instant in another offset does not).
- API: `MentorRequestCreate` / `MentorRequestPatch` take `due_at` (ISO 8601 with an offset). On create it must be
  in the future; on create and edit at most 365 days ahead (400 with `field`). An edit may keep or set a past
  deadline (so fixing an overdue request's title still works). Every `MentorRequest` adds `due_at`, `done_at`,
  `timing` (`no_deadline`, `upcoming`, `due_soon` ≤ 24 h, `overdue`, `done_on_time`, `done_late`) and
  `late_by_minutes` (overdue / done late only). `InternDetail.tasks` = `{total, done, done_on_time, done_late,
  overdue, open}` (total = done + open + overdue; null when the requests cannot be read). Counts only, no score
  words.
- Reminders (`app/reminders.py`): a daemon thread started in the app lifespan and stopped on shutdown, every 30 s;
  not started (and nothing logged) with OFFLINE=1 or SMTP unconfigured, so never in tests unless a test starts it
  with a fake clock. Requests not done, with a deadline, no claim and now ∈ [due_at − REMINDER_MINUTES, due_at):
  claim first (`reminder_sent_at`, a conditional write: id, same `due_at`, still null, not done), then queue the
  `request_reminder` email to the intern (Arabic first then English, RTL, the title and note, the deadline in
  Amman time, "open the onboarding assistant", no link). No late reminder after downtime; deactivated interns
  skipped; an intern without an email is claimed and logged `skipped / no_recipient` like other events. Setting
  `REMINDER_MINUTES` (default 10, 1–120) in `app/config.py` and `.env.example`. The new-request email shows the
  deadline in Amman time. `Mailer.submit` now starts a thread before listing it, so `wait` from another thread
  (shutdown, or the reminder thread queueing meanwhile) can no longer join a thread that has not started.
- Web: the admin request dialog has «الموعد النهائي» / "Deadline": a date and a time input in the browser's local
  time (a bare date fills 23:59), sent as ISO with the browser's offset, clearable; a new deadline must be in the
  future and within a year; an edit sends `due_at` only when it changed. Intern and admin request cards show the
  timing badge («يستحق خلال 3 ساعات» / "Due in 3 h", «متأخر 2 س» / "Overdue by 2 h", «سُلّم في الموعد» / "Done on
  time", «سُلّم متأخراً 1 س» / "Done 1 h late") and «الموعد النهائي: …» in Amman time; an open request is re-judged
  every minute. The admin's intern page shows a "Tasks" line (on time · done late · overdue · open) above the
  requests and re-reads it after a request is added, edited or deleted. The email log names the new event.
  New `web/src/lib/deadline.ts`, `components/requests/Deadline.tsx`, i18n block `deadline` (both languages).
- Contract: `schemas.py` (`RequestTiming`, `REQUEST_TIMINGS`, `TaskSummary`, `DUE_SOON_HOURS`, `DUE_AT_MAX_DAYS`,
  `request_reminder` mail event), `types.ts` (same + guards), fixtures `mentor_request*.json`,
  `mentor_requests*.json`, `intern_detail.json`, INDEX.md, `docs/api_contract.md` §6l, `tests/test_contract.py`.
- Privacy: `docs/privacy_ai_note.md` (what the reminder email carries, the stored columns, task counts are not an
  evaluation).
- Tests: `tests/test_deadlines.py` (rules, timing incl. reopen, due_date compatibility and backfill of an old
  SQLite file, API checks, task counts, both stores incl. Supabase over MockTransport and a missing migration,
  frozen-clock reminders: window, once only across two servers and a restart, no late send, cleared on a new
  deadline, done / deactivated skipped, silent when unconfigured, thread start/stop, lifespan, email text);
  `tests/test_mentor_requests.py` uses a future `due_date`; web `deadline.test.tsx` (rules and wording in both
  languages, Amman formatting, picker payload with offset, 23:59 fill, clear, past / missing-time errors, edit
  sends only a changed deadline, card badges, task counts).
