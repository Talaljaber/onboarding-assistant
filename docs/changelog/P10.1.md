# P10.1 — admin-only knowledge editor and manager view

- Server: `app/admin.py` checks the admin password (`ADMIN_PASSWORD`, demo default `dada2026`,
  4–64 characters) and issues a signed token `<expiry>.<hmac>` (per-process secret, 8 h by
  `ADMIN_SESSION_HOURS`). `POST /api/admin/login`, `GET /api/admin/session`. The KB writes
  (`PUT /api/kb/{id}`, `POST /api/kb`, `POST /api/kb/reset`) and `GET /api/manager/summary` need
  `Authorization: Bearer <token>` and answer 401 `unauthorized` before the body is validated.
  5 wrong passwords inside 60 s → 429 `too_many_requests`. `GET /api/kb` and every employee endpoint
  stay open. Contract: two error codes, `AdminLogin`, `AdminSession`, four fixtures, doc sections.
- Web: `#/admin` sign-in screen; `#/kb` redirects there without the token; the tools menu shows
  «دخول المسؤول» to employees and «قاعدة المعرفة» to the signed-in admin; sign-out on the editor;
  token in sessionStorage, checked on load, forgotten on any 401. Welcome screen links the sign-in.
- Tests: `tests/test_admin.py` (401 on every admin endpoint without/with bad tokens, login, 429,
  expiry and tampering, settings), web admin tests, route and nav tests; e2e step 14 now signs in
  (wrong password first, shot `14a_admin_sign_in`); smoke and `ui_shots.py` sign in.
- Results: 704 Python tests, 212 web tests, e2e 2/2, smoke OK offline, no overflow at 360–1280.
  Retrieval and answers are untouched, so the eval numbers do not change.
