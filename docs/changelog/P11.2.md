# P11.2 — sign-in first, interns managed by the admin

- **Sign-in first.** `#/` asks "Intern" or "Admin". An intern picks their name from the active interns
  (`GET /api/interns`) and gets the employee app (assistant, scenarios, plan, quiz, progress) on the track
  the admin set (`POST /api/interns/{id}/session`, get-or-create one profile per intern and track). The
  header chip shows the first name and the short track (a label, not a switcher); sign-out is in the
  settings sheet. Interns get no admin links. No intern password in this demo (said on the sign-in screen,
  README and privacy note: a production version adds real authentication). Older anonymous sessions start
  signed out.
- **Admin shell.** After the password sign-in the admin gets its own header and navigation (Interns,
  Knowledge base, sign out; a tab row on phones; no intern bottom bar). The KB screen lost its manager tab
  and its own sign-out.
- **Interns (admin).** `GET/POST /api/admin/interns`, `PATCH /api/admin/interns/{id}` (names, track,
  `active` for a soft delete), `GET /api/admin/interns/{id}` (plan with completion dates, scenarios practised,
  quiz questions answered per day, chat question count and cited K-rows from turn logs, timeline). Counts
  and dates only, never correctness or scores, never chat text. `GET /api/manager/summary` and
  `ManagerSummaryResponse` are removed (replaced by the interns list).
- **Data.** New `interns` table and `profiles.intern_id` (unique per intern and track):
  `supabase/migrations/0002_interns.sql` (to apply after 0001) and the same change on open in
  `LocalStore`. The four fictional interns are seeded at startup only when the table is empty.
  `scripts/purge_demo_profiles.py` (dry run by default, `--apply`) removes profiles without an intern with
  their progress and attempts and clears their turn-log links. `POST /api/profiles` stays as a legacy
  endpoint; the web client no longer uses it.
- **Progress follows the intern.** The client loads the server's ticks at sign-in and when the page is
  shown again (server wins), so every browser and the admin agree.
- **Privacy.** Names never reach LLM prompts, chat requests, turn logs or generated text; a test checks
  that answer/agent/LLM/prompt code never imports the interns module or holds a seeded name.
- **Tests.** `tests/test_interns.py` (roster, sessions, add/edit/deactivate, every intern action in the
  detail and list, purge script), store tests for both stores (MockTransport, unique-index race), contract
  fixtures `interns`, `intern_session`, `admin_interns`, `intern_create_request`, `intern_patch_request`,
  `intern`, `intern_detail`; web tests for sign-in, session refresh, sign-out, the admin shell routes, the
  interns list (names per language, add form validation) and the detail page. `scripts/smoke_api.py`,
  `scripts/ui_shots.py` and `tests/e2e/test_smoke.py` sign in as interns (one per viewport, since progress
  now follows the intern on the shared test server) and walk the admin interns list and detail.
