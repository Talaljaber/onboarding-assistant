# P23.2 — quiz runs in the web client (resume, time limit, leave-guard, lock, report)

Owner request: the quiz state was not saved, the intern could leave and start over, the admin wants a time limit,
and the end of a quiz should be a report of what happened. The web client now uses the P23.1 run API for every
quiz (the official sample quiz and the admin's sets); the old per-question `/api/quiz/check` flow is gone from the
runner (`postQuizCheck` stays in the client for compatibility).

## Intern
- **Start or resume** (`QuizRunner.tsx`): opening a quiz calls `POST /api/quiz-runs`; an open run comes back with
  the same questions, order and answers, on the first unanswered question, with the time left.
- **One question at a time** (`RunView.tsx`): «اعتمد الإجابة» sends the answer, which is then locked and not
  revealed («إجابتك محفوظة…»); «السابق» / «التالي» and a question map (one dot per question, 44 px on phones,
  "Question 3: not answered" for screen readers) to jump to any question; «إنهاء الاختبار» asks first while some
  are unanswered.
- **Countdown** (`Countdown.tsx`) for a set with a time limit: mm:ss, a polite live region once a minute and once
  under a minute, red under one minute, auto-finish at zero. The server's `remaining_seconds` is the truth, read
  at start and again with every answer; `reason:expired` / `reason:finished` lead to the report.
- **Leave-guard** (`useLeaveGuard.tsx`): in-app links and the back button during an open run ask with the plan's
  wording («الاختبار ما زال مفتوحاً…»); `beforeunload` while a run is open; router redirects pass.
- **Quiz lock** (owner addition): a locked run (checkpoint or timed set, `locked` from the server) turns the bottom
  bar and the side rail into «أنهِ الاختبار أولاً» (`quizLock.ts`, `NavBars.tsx`) and its leave dialog has no
  "leave" button («هذا اختبار مقفل…» + «العودة إلى الاختبار»). An intro before a locked run says the assistant and
  Rumour Check are closed until the end. The chat renders the server's lock reply (`quiz_lock`) as a calm notice
  with «العودة إلى الاختبار» (`QuizLockNotice.tsx`); Rumour Check sends the profile id and shows the same notice on
  `reason:quiz_open`. Signing out of an open run asks first (Header).
- **Report** (`RunReport.tsx`): the intern's own result ("4 / 5"), how many were not answered, a time-up note for an
  expired run, then each question with right / wrong / not answered, the intern's answer, the correct answer and
  the cited K-row verbatim; a wrong or missing answer offers «اسأل المساعد» (question, options and pick, P22.1) and,
  for sets, «اسأل مشرفي عن هذا». «أعد المحاولة» starts a new run (the server puts the missed questions first). The
  URL becomes `#/quiz?set=<id>&review=<run>` so a reload shows the report again.
- **Checkpoints**: the notice before the first run (unchanged wording); the first run's report is labelled the
  shared result; later runs show the shared result and «هذه المحاولة للتدرّب…». `SharedResultLine` gains `final`
  (a finished first run with unanswered questions shows "1 / 3", not "answered so far").
- **Quiz list**: «متابعة» with the time left for an open run, «عرض آخر نتيجة» for the last finished run, «لم يكتمل»,
  and the time-limit badge ("10 د" / "10 min").
- The official quiz is a run too (never timed or locked); finishing it still records the browser's practice
  attempt and ticks the Day 30 quiz activity (the server ticks it too).

## Admin
- Set editor: «مدة الاختبار (دقائق)» (text box, numeric keypad, Arabic-Indic digits accepted; empty = no limit;
  1–120) with the plan's hint; saved as `time_limit_minutes` (null clears it). Sets list and editor header show the
  limit badge.

## i18n
New block `quizRuns` at the end of `ar.ts` / `en.ts` (the run screen, report, list, lock and admin wording).
