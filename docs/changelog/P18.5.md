# P18.5: private replies to interns' questions

Owner: "sometimes the answered question is a personal one that depends on the intern themself, so we should make
it both scenarios: add to knowledge base or just respond to the intern themself".

- API: `QuestionAnswer` gains `scope: "kb" | "private"` (default `"kb"`: unchanged behaviour, `topic` still
  required). `scope: "private"`: `answer_ar` (same 5–600 limit and the same no phone/email/link check) is stored
  on the question as `answer_text`; no K-row, no re-index, no version bump; `topic`, `keyword_en` and
  `source_document` are not used. `QuestionAnswered.row`, `.version` and `.reindex_ms` are nullable (null exactly
  for a private reply; a model check enforces it). `MentorQuestion.answer_text: string | null` (an answered
  question has exactly one of `answer_row_id` and `answer_text`), returned only through the existing scoped routes
  (the owning intern and the admin). The route logs `scope` only, never the text.
- Data: migration `supabase/migrations/0008_private_answers.sql` (**the integrator applies it**, idempotent):
  `mentor_questions.answer_text` (1–600 after trim), drops `mentor_questions_answered_has_row` and adds
  `mentor_questions_answered_has_one_answer` (answered ⇒ exactly one of row id / text; otherwise both null).
  LocalStore: the same column in the schema, added on open to an older SQLite file. `QUESTION_COLUMNS` includes
  `answer_text`; `question_changes` accepts `{status: answered, answer_text}`.
- Email: `mailer.question_answered_private(mailer, *, intern_id, question, answer_text)` → the intern, Arabic
  first, saying it is a personal reply from the mentor and not part of the knowledge base (no K-id). Logged as
  the existing `question_answered` event (no `mail_log` constraint change). The "new question" email to the
  admin now mentions both ways to answer.
- Web: the answer dialog has a choice «أضفه إلى قاعدة المعرفة» (default) / «ردّ على المتدرب فقط»; the private
  choice hides topic, keyword and document and shows «لن يُضاف إلى قاعدة المعرفة ولن يراه غير هذا المتدرب»;
  the dialog title is now «أجب عن سؤال المتدرب». The intern's «أسئلتك لمشرفك» shows a private reply as the
  mentor's message labelled «ردّ خاص من مشرفك — ليس من قاعدة المعرفة», with no K-id and no «أعد السؤال». The
  admin list shows the reply with a «ردّ خاص» tag. English strings for all of it.
- Contract: fixtures `question_answer_private_request.json`, `question_answered_private.json` (new),
  `answer_text` in every question fixture, one privately answered question in `questions.json` and
  `admin_questions.json`, `scope` in `question_answer_request.json`; INDEX.md, `docs/api_contract.md` §6k,
  `tests/test_contract.py`.
- Privacy: `docs/privacy_ai_note.md` says private replies are stored on the question row and shown only to that
  intern and the admin; never the KB, the index, a prompt or a turn log.
- Tests: `tests/test_questions.py` (no KB change, intern-only visibility, contact and length checks, once only,
  not in turn logs or KB rows, explicit `kb` scope, old SQLite file gains the column, both stores incl. Supabase
  over MockTransport), `tests/test_mailer.py` (hook and route, smtplib mocked), web `questions.test.tsx` (dialog
  choice, hidden fields, contact check, payload, toast, admin tag, intern display; Arabic and English).
