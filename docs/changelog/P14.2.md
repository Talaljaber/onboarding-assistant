# P14.2: Rumour Check «سمعتها بالمعرض»

- `POST /api/check` `{text ≤ 600, force_offline?}` → `CheckResponse {claims ≤ 5, truncated, mode, label_ar}`.
  The text is split on `. ، ؛ ؟ !` and line breaks only; every claim is the user's own substring (with its
  offset). No store write and no turn log (tested: `turn_metrics()` unchanged, no store method called).
- Guards first (`app/guards.run_guards` on the claim and on the claim without a leading «و», since the pay
  pattern takes one proclitic only: «والراتب»): a guarded claim gets the fixed `guarded` label, no row, and
  is never sent to the model.
- Offline rules (corrected per review §3 C2/C3), `app/factcheck.py` + `app/verify.compare_claim`:
  candidate row = the row `margin().best_row_id` and `search()[0]` agree on (band `refuse` or disagreement →
  `not_found`; the answer band is not required). `supported` = the claim is a normalised substring of the row,
  or every claim number (`numbers_in`) equals a row number whose following word matches by normalised prefix
  («17 معرض» ↔ «17 معرضاً», «تسعين يوم» ↔ «90 يوماً»). `differs` = same unit word, another number (the two
  numbers are returned as verbatim spans: struck / highlighted on the card). Ordinals and unit-words
  («الأول»، «الثاني»، «شهر»، «شهرين»، «سنة») never form a number-and-unit pair, and a negation or limiting
  word the row lacks («مش»، «ما»، «بس»، «فقط»، «بدون» …) blocks `supported` / `differs` → `related`. Otherwise
  `related`. The review's offline table passes, including «فترة التجربة شهرين» / «شهر واحد» never `supported`
  and «3 شهور» `related`, never `differs`.
- Model layer (one call per check, `app/llm/paths.llm_check`, prompt `prompts/check_v1.md`): reply
  `{"claims": [{i, label, id, quote}]}` with labels `supported | contradicts | related | not_found`.
  `verify.verify_check`: shape, sent index once, enum, one sent row id (none for `not_found`), `quote_in_row`
  for `supported` / `contradicts`; a `supported` failing the number rule is downgraded to `related` (never a
  contradiction). A claim that fails keeps its offline label; an offline `differs` is kept unless the model
  says `contradicts` on the same row (then shown as `differs` with the numbers). Cached only when every claim
  passed with nothing rejected or downgraded; cache hits re-verified. No call for injection-like text, for
  only-guarded text, or with `force_offline`. The model's quote is checked, never shown.
- Contract: `app/schemas.py` (`CheckRequest`, `CheckResponse`, `CheckClaim`, `CheckNumbers`, `CHECK_LABEL_AR`),
  `web/src/api/types.ts`, `contracts/fixtures/check_request.json` + `check.json` (server output for the
  sample), `INDEX.md`, `docs/api_contract.md` §6f and §7, `tests/test_contract.py`.
- Web: `#/check` screen (`components/check/CheckScreen.tsx`): text box (600 limit, counter), «افحص», «جرّب
  مثالاً»; one card per claim with a fixed label (icon + words), the user's sentence (the heard number struck
  for `differs`) and the row verbatim (the row's number highlighted); footer «هذا فحص للمعلومة، وليس حكماً على
  أحد». Nav: sidebar learn group, the phone settings sheet, and one first-turn chat chip «سمعتها بالمعرض؟
  افحصها» that opens `#/check?sample=1` (sample filled in and checked once). The phone bottom bar keeps its five
  screens. i18n block `check.*` (ar + en).
- Dev data: `data/ours/factcheck_dev.csv` (24 rumours written from the official rows, expected and acceptable
  labels). `scripts/eval_factcheck.py`: offline columns always; LLM columns `not_run` without a key, with
  OFFLINE=1, `--offline-only` or a failed probe; reports `false_supported` (exit 1 if any) and `false_red`.
  Offline run here: exact=4/24, false_supported=0, false_red=0 (the rules prefer `related`).
- Kill-switch setting `LLM_CHECK` (`Settings.llm_check`, default **0** = the offline rules in both modes;
  `.env.example` documents it). The eval script calls the model layer directly, so it runs either way.
- Integrator: run `.venv\Scripts\python.exe scripts\eval_factcheck.py` in the main folder with the key; set
  `LLM_CHECK=1` in `.env` only with 0 false `supported` and a manual review of every `supported` (review §2
  item 2 kill-switch). Otherwise leave it at 0: the screen works with the offline rules.
