### P8.4 — Eval harness for the answer panel and the second sealed set  (Opus, 2026-11-11)
- What now exists:
  - `scripts/run_eval.py`: `--set heldout2` sealed exactly like `heldout` (exit 2 without `--final`, file never
    opened, aggregate-only printing); rows go to `results/results_heldout_2_final.csv`. `--set all` = dev + jury,
    plus heldout + heldout2 only with `--final`. New per-row columns from `trace.panel` and the budget delta.
  - `scripts/score_results.py`: "Held-out 2 (final run)" aggregate block; every llm block adds panel stats.
  - `scripts/pick_panel.py` (new): what-if table of `LLM_PANEL_ACCEPT` 0.50–0.95 on a DEV llm results file.
  - Tests: `tests/test_eval_scripts.py` (panel columns, cost, stats, pick_panel, heldout2 paths, fixture rows
    built in the tests), `tests/test_sealed.py` (heldout2 exit 2 incl. `--mode llm`; hash check per sealed file).
- Interfaces added/changed: `results.csv` appends `panel_confidence` (2 decimals), `panel_accepted` (true/false),
  `panel_escalated_to`, `panel_votes` (`role:ok|no:conf[:cached]` joined by `;`), `turn_cost_usd`
  (`agent.llm.budget.spent()` after − before, the whole row incl. its second turn; empty without a budget).
  Panel columns come from the first turn's trace and are empty when `trace.panel` is absent.
  `score_results`: `HELDOUT2_FILE`, `SEALED_FILES`, `panel_stats`, `panel_lines`, `flash_calls`, `row_escalated`.
  `run_eval`: `SEALED`, `HELDOUT2_CSV`, `panel_columns`, `spent_usd`.
- How to use it: `& $VPY scripts\run_eval.py --set dev --mode llm` then `& $VPY scripts\pick_panel.py
  results\results.csv`; once, after freeze-2: `& $VPY scripts\run_eval.py --set heldout2 --mode llm --final`.
- Config/env: none new.
- Acceptance: `& $VPY -m pytest -q` → 653 passed; ruff → All checks passed!;
  `& $VPY scripts\run_eval.py --set heldout2 --mode llm ; $LASTEXITCODE` → 2.
- Limitations / TODO:
  - The file is `results_heldout_2_final.csv`, not `results_heldout2_final.csv`: the latter misses the
    `results/*_heldout_*` git-ignore rule.
  - Summary panel stats are per eval row (a scenario/progress row is two turns): "flash calls/row" counts
    uncached non-escalation votes of the first turn's panel; "cost per 100 rows" uses the budget delta.
    The p50/p95 split treats a row as escalated when `panel_escalated_to` is set or `escalated` is true.
  - `pick_panel.py` sees one outcome per row (flash draft if accepted, escalated answer if escalated); thresholds
    that change a row's decision leave it unknown, shown as a low–high range. Its pick (best observed correct,
    then fewest escalations) leans to the run's own threshold; a fair comparison needs two DEV runs
    (ACCEPT=0 and ACCEPT=1). It refuses files named `*heldout*` / `*jury*`.
  - Not run against the real panel (P8.2 lands separately); the trace shape follows `TracePanel` in `app/schemas.py`.
