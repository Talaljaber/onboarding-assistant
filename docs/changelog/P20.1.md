# P20.1: practice quizzes written by the admin (backend, contract, migration)

Owner: the admin writes quizzes, assigns them to interns or a track, they open at a progress level, a model helps
write questions or a file is uploaded, interns retry. Integrator's plan (P20 PLAN.md) plus the owner's later
checkpoint decision (D-P20-checkpoint).

- Contract (two commits, additive after the first): `app/schemas.py`, `web/src/api/types.ts` (guards,
  `quizErrorReason`), `web/src/api/client.ts` (15 functions), 24 fixtures, `contracts/fixtures/INDEX.md`,
  `docs/api_contract.md` §6l, `tests/test_contract.py`. `QUIZ_ID_RE` is `^(Q\d{2}|M\d{3})$`; `QuestionSource`
  gains `"quiz"`; `InternDetail` gains `checkpoints` (default `[]`).
- Grounding: `app/quiz_sets.py::check_item` (one function for typed items, model drafts and CSV lines): the row
  exists, question 5–300 and options 1–120 characters, three distinct options, no contact or link, every number of
  the question and the correct option in the row (distractors may differ). Model drafts also: ≥ 50 % of the correct
  option's content words in the row, no other option found in the row, no honorific name. Failures are 400
  `validation_error`, the field, and `reason:<code>` in the message (the error enum is unchanged).
- Routes (`add_quiz_set_routes`): admin CRUD for sets and items, reorder, CSV import (official `sample_quiz.csv`
  columns, per-line reasons, 20-item cap; a 300 KB body on that route with an admin token), model draft (pinned
  flash, one GLM-5.3 escalation when the draft fails the checks, cached only after verification; 503
  `imports_unavailable` with `reason:llm_unavailable` / `reason:draft_failed`), anonymous signals (≥ 3 interns,
  first answer per intern; also `official`), checkpoint results. Intern: `GET /api/quiz-sets` (official first, then
  published sets for them, open by suggested-plan progress), `GET /api/quiz-sets/{id}` (404 not visible; 400
  `progress` `reason:locked:<n>`), `POST /api/quiz/check` with `M` ids (visible and open only), `POST
  /api/questions` with `source: "quiz"` (the admin email says it came from a practice quiz).
- Checkpoints (D-P20-checkpoint): `mode` practice|checkpoint per set; for checkpoint sets only, the earliest attempt
  per (intern, question) over all the intern's profiles is shown to the admin (`GET …/results` and the intern
  detail's `checkpoints`). Later attempts never change it; the mode cannot change once anyone answered; practice
  sets and the official quiz never appear in any admin shape (tests scan every admin response).
- Store: `quiz_sets`, `quiz_set_items` and `quiz_answers` methods on the protocol, LocalStore (SQLite tables; an
  older `mentor_questions` table is rebuilt on open to accept `quiz`) and SupabaseStore (never flips to local; 503
  `requests_unavailable` without the tables). Item ids: the next M number after every id held by an item or a
  stored attempt (a 409 race retries once).
- Migration `supabase/migrations/0009_quiz_sets.sql` (idempotent; RLS on, no policies, revoked from anon and
  authenticated; also widens `mentor_questions_source_check` to `quiz`). **The integrator applies it.**
- Prompt `prompts/quiz_draft_v1.md` (one row in; JSON out). Tests use a fake client only; no real model call.
- Docs: `docs/privacy_ai_note.md` (what is sent for a draft, the new tables, §8 practice vs checkpoint).
- Tests: `tests/test_quiz_sets.py` (17), `tests/test_contract.py` (practice quiz and checkpoint contract, the
  admin scan with the commented allow-list), `web/src/api/__tests__/quizSets.test.ts`.
