# P13.1 — "Before your first day" card and admin KB coverage

## What

- **Before your first day (قبل يومك الأول)** — `web/src/components/welcome/FirstDayCard.tsx`, shown on the
  signed-in intern's assistant screen (`#/chat`, the intern's home after sign-in) while the thread is empty
  and no practice is running. A closed disclosure card by default; opened, it shows:
  - the suggested plan's **Days 1–7** activities for the intern's track, from the plan the app already loads
    (`useAppState().plan`), with the "suggested" badge and "a suggested learning plan, not official policy";
  - the onboarding K-rows **K11** (prepared before you start), **K12** (first-day orientation) and **K13**
    (welcome email within the first three days), quoted verbatim with id, document and page via the existing
    `KRowQuote` from the open `GET /api/kb` (loaded on first open only). These are the only KB rows about the
    time before/at the start (checked against `data/official/knowledge_base.csv`). A row the admin removed is
    left out; an edited row shows its live text with the "edited live" badge;
  - one sample question chip («ماذا يحدث في اليوم الأول؟» / "What happens on the first day?") linking to
    `#/chat?ask=…`, which prefills the composer (never auto-sends). Offline both versions answer from K12.
  - In-app only, behind sign-in: no public link, no new server route. Labels in the `firstDay` i18n block
    (Arabic primary, English UI in English; K-rows and plan titles stay Arabic with `lang="ar"`).
- **KB coverage (admin)** — `GET /api/admin/kb/coverage` (admin only, `ADMIN_ONLY`) → `KbCoverage`:
  `total_turns`, `kb_rows`, `top_cited` (≤ 8 rows, most cited first, with topic and keyword), `never_cited`
  (current rows with no citation), `windows` for the last 7 and 30 days (`turns`, `questions` = turns with an
  answer status, `refusals` = `unsupported` turns, `refusal_share` = refusals / questions) and `since`.
  - Counting in `app/coverage.py` (pure). Input is a new `Store.turn_metrics()` returning
    `{status, band, cited_ids, at}` per turn log — never `profile_id`, never text — in `LocalStore` (SQLite)
    and `SupabaseStore` (PostgREST, paged by 1000 with `limit`/`offset`, local fallback as every call).
    `turn_log_record` and the turn-log columns are unchanged: the store still never keeps chat text.
  - Card `web/src/components/admin/KbCoverageCard.tsx` at the bottom of the admin home (`#/admin/interns`):
    two window tiles, the most-cited list with a quiet bar, the never-cited list, each id linking to
    `#/kb?row=Kxx` (opens that row in the editor) plus "Open the knowledge base". Aggregate and anonymous:
    no names, no per-intern figure, no ranking, no "behind" / "needs attention" wording.
  - Contract triplet: `app/schemas.py` (`CoverageRow`, `CoverageWindow`, `KbCoverage`, `COVERAGE_TOP`,
    `COVERAGE_WINDOWS`), `web/src/api/types.ts` (types + `isKbCoverage`), `web/src/api/client.ts`
    (`getKbCoverage`), `contracts/fixtures/kb_coverage.json` + `INDEX.md`, `docs/api_contract.md` §6d,
    `tests/test_contract.py`.

## Why

New interns ask what happens before and on day one; the answer already exists as cited K-rows and in the
suggested plan, so the card puts them together without new data or a new route. The admin needs to see where
the knowledge base has gaps (refused questions, rows nobody needs) without turning usage into a judgement of
people, so the coverage view is aggregate only.

## Decisions

- Refusal = turn with status `unsupported` (every refusal reply, incl. employment) or band `refuse`; the share
  is over Q&A turns (`questions`), not over all turns (plan, quiz, scenario and small-talk turns would dilute
  it); `turns` is still reported per window.
- A row cited twice in one reply counts once for that turn. Cited ids no longer in the KB keep their count
  with `topic`/`keyword_en` null ("Removed row").
- The first-day card lives on the assistant screen because a signed-in intern's `#/` redirects there; it hides
  once the conversation starts (Clear brings it back).
