# P18.2: email notifications (Gmail SMTP)

- `app/mailer.py` (standard library only: `smtplib`, `ssl`, `email.message.EmailMessage`, `threading`):
  `SMTP_PORT=465` → `smtplib.SMTP_SSL` (implicit TLS, no STARTTLS); any other port (default 587) → `smtplib.SMTP`
  + EHLO + STARTTLS (verifying `ssl.create_default_context()`) + EHLO; then login with `SMTP_USER` and the app
  password with its spaces removed, and `send_message`. 15 s socket timeout. Each event runs in a daemon thread
  started after the store write succeeded: no route waits on SMTP, a failure never reaches the user.
- Every email is recorded in `mail_log`: `sent`, `failed` (code: `auth_failed`, `timeout`, `connect_failed`,
  `tls_failed`, `recipient_refused`, `sender_refused`, `smtp_error`, `error`; never the SMTP reply) or `skipped`
  (`offline`, `not_configured`, `no_recipient`). OFFLINE=1 or a missing user/password never connects.
- Events (Arabic-first: RTL HTML + plain text, English under the Arabic, "open the onboarding assistant", no
  links): request created → intern; admin comment → intern and intern comment → `ADMIN_EMAIL`, with the comment's
  files attached; intern marks a request done (only on the change to done) → `ADMIN_EMAIL`. Hooked in
  `app/api.py` (`admin_request_add`, `requests_own_status`, `add_comment`).
- For P18.1 (not wired here; the integrator adds them to the questions routes after the store write):
  `mailer.question_submitted(mailer, *, intern_id, text, source)` → `ADMIN_EMAIL` and
  `mailer.question_answered(mailer, *, intern_id, question, row_id, answer_ar)` → the intern, with the answer row
  verbatim and its K-id. The `Mailer` is `request.app.state.mailer` (`api._mailer(request)`); both accept None.
- Settings (`app/config.py`, `.env.example`): `SMTP_HOST` (smtp.gmail.com), `SMTP_PORT` (587; 465 supported),
  `SMTP_USER`, `SMTP_PASSWORD` (SecretStr), `MAIL_FROM` (default SMTP_USER), `ADMIN_EMAIL`; empty = unset;
  bad addresses or host stop startup with the one-line fix. Gmail app-password how-to in `.env.example`.
- Data: migration `supabase/migrations/0007_email.sql` (**the integrator applies it**): `interns.email` (checked
  shape) and `mail_log` (RLS on, no policies, revoked from anon/authenticated, idempotent). LocalStore: the same
  column and table. Store methods `intern_email`, `set_intern_email`, `mail_log_add`, `mail_log`; on Supabase
  they never flip to local (without 0007 only email features are unavailable: the email reads as none, the log
  route answers 503 `requests_unavailable`).
- Contract triplet: `InternOut.email`, `InternCreate.email`, `InternPatch.email` (optional, `""`/null = none,
  admin views only, never in `InternPublic`); `GET /api/admin/mail/log` → `MailLogResponse` (last 50, plus
  `configured`, `admin_email_set`); `POST /api/admin/mail/test` → 202 `MailTestResponse` (queued/skipped).
  Fixtures `mail_log.json`, `mail_test.json` (+ `email` in the intern fixtures), INDEX.md, api_contract.md §6j.
- Web: email field in the add/edit intern dialog (same rule as the server); «سجل البريد» / "Email log" card on
  the admin interns screen (table from md, cards on phones; status with reason; set-up notice; «أرسل رسالة
  تجريبية إليّ» / "Send a test email to me", the log re-read 3 s later); privacy lines in the card, About and
  `docs/privacy_ai_note.md`. i18n block `mail` at the end of `ar.ts` / `en.ts`.
- Tests: `tests/test_mailer.py` (smtplib mocked: 587 STARTTLS path, 465 SMTP_SSL path without STARTTLS,
  attachments, skipped offline/unconfigured/no address, failures recorded with codes, background thread does
  not block, password absent from logs/responses/rows/repr, both stores incl. Supabase without 0007, API
  events, intern email routes), `tests/test_contract.py` (new fixtures), `web/.../MailLogCard.test.tsx`,
  `tests/e2e/test_email.py` (Chromium, 1280 and 360, Arabic and English; run with `E2E_PORT` in 8120-8129).
- Owner setup: set `SMTP_USER`, `SMTP_PASSWORD` (Gmail app password), `ADMIN_EMAIL` (and `SMTP_PORT=465` if
  used) in `.env`, restart, then press «أرسل رسالة تجريبية إليّ» and check the email log.
