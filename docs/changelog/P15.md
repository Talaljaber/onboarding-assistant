# P15: comments and files on mentor requests

- Both ways on one request: the intern answers ("done, here is what I learned"), the admin replies. A comment is
  text (0–1000 after cleaning, request contact rule → 400 `field: body`) and/or up to 3 files; one of the two
  is required (400 `field: body`). No edit or delete of comments, no unread state, no notifications, no previews.
- Files: `.pdf` / `.docx` / `.png` / `.jpg` / `.jpeg` by extension **and** magic bytes (`%PDF-`; a zip with
  `word/document.xml` inside the import's zip-bomb limits; PNG signature; `FF D8 FF`), 1 byte to 5 MiB decoded,
  base64 in JSON like the document import; anything else → 400 `field: files`. Names reduced to a safe base name
  (no folders, control or bidi characters), extension kept, ≤ 120. `app/request_comments.py`.
- Routes (contract triplet: `app/schemas.py`, `web/src/api/types.ts`, fixtures `request_thread.json`,
  `request_comment.json`, `request_comment_create_request.json`, `request_comment_admin_create_request.json`,
  `INDEX.md`, `docs/api_contract.md` §6h, `tests/test_contract.py`):
  `GET|POST /api/requests/{id}/comments`, `GET /api/requests/{id}/files/{file_id}` (intern, scoped by the session
  profile id like the other request routes: another intern's request or file → 404) and the same three under
  `/api/admin/requests/{id}/…` (admin token). Downloads: stored content type, `Content-Disposition: attachment;
  filename*=UTF-8''…`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`. `MentorRequest` gains
  `comment_count` (additive; 0 when the store has no comment tables yet, so requests keep working before 0005).
- Body limit: the two comment POST routes accept `COMMENT_BODY_MAX_BYTES` (3 × base64 of 5 MiB + 64 KB; the admin
  route only with a valid token); every other route keeps 32 KB.
- Storage: migration `supabase/migrations/0005_request_comments.sql` (tables `mentor_request_comments`,
  `mentor_request_files` with cascades, RLS on, no policies, revoked from anon/authenticated, idempotent; the
  **private** bucket `mentor-files`). `SupabaseStore` uploads / downloads with the secret key through the Storage
  REST API (`POST|GET {SUPABASE_URL}/storage/v1/object/mentor-files/requests/{request_id}/{file_id}`, `x-upsert:
  false`, content type set, 30 s timeout) and removes the objects when a request is deleted (best effort). A
  failure → 503 `requests_unavailable`, never a flip to local. `LocalStore`: the same tables in SQLite and the
  bytes under `data/live/mentor_files/{request_id}/{file_id}` (git-ignored), removed with the request.
- Web: «الردود (n)» on each intern request card and on each request of the admin's intern page
  (`components/requests/RequestThread.tsx`): author labels «أنت» / «المشرف» (intern) and «المتدرب» / «أنت
  (المشرف)» (admin), time, text, file chips that download through the app (fetch + blob + object URL; admin token
  on admin paths), a reply box with «إرفاق ملف» and client checks (type, empty, 5 MB, 3 files, length, contact,
  empty reply). i18n block `requestThread` (ar + en).
- Honest labelling: `docs/privacy_ai_note.md` (attachments and replies are stored, imports still are not; the
  name-only intern sign-in lets anyone at the device act as an intern; files are not virus-scanned) and README.
- Tests: `tests/test_request_comments.py` (both ways, scoping 404s, 401s, validation incl. wrong magic bytes,
  6 MiB, 4 files, empty, contact; download headers; cascade delete; comment_count; no text in chat or turn logs;
  503; body limits), `tests/test_store.py` (both stores; Supabase Storage over `httpx.MockTransport`: upload
  headers, download, delete, a 503 path, roll-back when the file rows fail, no migration 0005),
  `web/src/components/requests/__tests__/thread.test.tsx`.
- Integrator: apply `0005_request_comments.sql` (tables + private bucket), check read-only against the real
  project (bucket `public = false`; an upload / download round trip with the server), build `web/dist`.
