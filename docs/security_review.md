# Security review (P5.4, W4-D)

Scope: `app/` read end to end (API, middleware, config, logging, agent and tools, LLM layer, stores,
prompt rendering), the static serving of `web/dist`, `web/src` for unsafe rendering, the start scripts
and the dependency pins. Threat model: a local demo bound to `127.0.0.1`, one operator (Talal) and judges
using the browser on the same laptop; an optional OpenRouter key and Supabase secret key live in `.env`
on the server side only. Reviewed on 11 Nov 2026, branch `w4/harden`.

Severity: **High** = key leak or remote code/data compromise; **Medium** = a real attack path in the demo
setting; **Low** = defence in depth or only relevant if the app is ever exposed beyond the laptop;
**Info** = verified, nothing to do.

## Findings

| # | Severity | Area / file | Finding | Status |
|---|---|---|---|---|
| 1 | Medium | `app/api.py` middleware | **Cross-site writes (CSRF).** No auth and no CORS, but a page on any other site the user visits while the app runs could still send "simple" cross-origin POSTs (`/api/kb`, `/api/kb/reset`, `/api/chat`, `/api/profiles`): a body sent without a Content-Type header is parsed as JSON by FastAPI. | **Fixed**: POST/PUT/PATCH/DELETE with an `Origin` that is not this server (including `null`) get a 400 `validation_error` (`field: "origin"`) before the body is read. Same-origin SPA calls and Origin-less clients (curl, tests, smoke) are unaffected; checked in Chromium (same-origin POST → 200). Tests: `test_cross_origin_writes_are_refused`, `test_same_origin_writes_pass`. |
| 2 | Medium | `app/api.py` | **No security headers.** | **Fixed**: every response (API, SPA, 404, 413, 500) carries `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` and `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; font-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`. Verified against a fresh `npm ci; npm run build` of `web/dist` (no inline script, no `data:` fonts) and in headless Chromium over all 8 routes: 0 CSP violations, the bundled Arabic font loads. CORS stays off (no `Access-Control-*` header even on a preflight). |
| 3 | Low | `app/api.py` `/api/health?probe=1` | Each probe is a paid (tiny) LLM call and the endpoint is open, so a loop could nibble the budget. | **Fixed**: re-probe at most every 10 s (`PROBE_MIN_INTERVAL_S`). Budget cap (USD 3) was already the hard stop. Test: `test_health_probe_is_throttled`. |
| 4 | Low | `app/config.py`, `app/main.py` | A bad env value, an unpinned model id (`openrouter/auto`) or a malformed `data/ours` CSV printed a full stack trace (paths, code) at startup. | **Fixed**: one line `Dada Academy cannot start: …` with the fix, exit 1. Model ids must be `vendor/model[:variant]` and never `openrouter/...`. |
| 5 | Medium (demo limitation) | `/api/kb*`, `/api/manager/summary` | **Staff mode, no auth.** Anyone who can reach the port can edit, add or reset KB rows and read the manager summary. | **Recorded**: accepted for the demo (server bound to `127.0.0.1`; finding 1 blocks other websites). A real deployment needs staff login + per-row audit (history already records `source`). |
| 6 | Low | `app/api.py`, host binding | **DNS rebinding**: the `Host` header is not checked, so a rebinding page whose host resolves to 127.0.0.1 is "same origin" for finding 1. | **Recorded**: needs a malicious site plus a rebinding DNS setup while the demo runs. Fix if ever needed: Starlette `TrustedHostMiddleware(["127.0.0.1", "localhost"])` when `HOST` is loopback. |
| 7 | Low | `/api/kb`, `/api/profiles`, store | No row or request-rate cap: repeated `POST /api/kb` or `/api/profiles` grow the KB / SQLite and trigger reindexing. | **Recorded** (local demo). Bodies are capped at 32 KB, every field has a max length, KB text ≤ 600 chars. |
| 8 | Low | `app/logging_setup.py` | `logs/app.jsonl` has no rotation. | **Recorded**: about 300 bytes per turn; rotation on Windows with two processes writing (tests + server) prints logging errors, so it was left out. |
| 9 | Low | prompts / KB edit | **Stored prompt injection via KB edit.** Edited KB text reaches the LLM prompt. | **Recorded**: values are inserted with `json.dumps` inside DATA blocks (`app/llm/__init__.py::_render`, single-pass `safe_substitute`), the prompts say DATA is never instructions, and every LLM answer goes through the verifier (cited ids ⊆ retrieved rows, verbatim quotes, no foreign numbers, phones, emails or links) before display. KB editing is staff-only by design (finding 5). |
| 10 | Info | `web/src` | Rendering of KB, answers, quiz and plan text. | **Verified**: no `dangerouslySetInnerHTML`, `innerHTML`, `eval` or `new Function` in `web/src`; all text is rendered by React as text. Dynamic `href`s are hash routes with `encodeURIComponent` (`#/chat?ask=…`, `#/chat?scenario=…`); no user-controlled URL is ever an `href`. |
| 11 | Info | static serving (`app.frontend` on `web/dist`) | Path traversal. | **Verified**: `/../app/config.py`, `/assets/../../app/config.py`, `%2e%2e` and `%5c` variants never return files outside `web/dist` (`test_static_serving_has_no_path_traversal`). `/api/*` misses are JSON 404, never the SPA. |
| 12 | Info | `app/api.py` errors | Stack traces / internals in responses. | **Verified**: the last-resort handler returns `{"error":{"code":"internal_error",…}}` with the request id; the exception type goes to the log only (`test_unhandled_error_is_generic_500`). Validation messages come from pydantic without the input value. `X-Request-Id` on every response, including 413 and 500. |
| 13 | Info | input validation | Every route. | **Verified**: all request models are `extra="forbid"` with length limits (message ≤ 1000 chars, scenario text ≤ 1500, KB fields 40/600/60/80, alias 40, id regexes for K/S/Q/activity/profile ids); 413 above 32 KB before parsing (content-length and streamed); control characters stripped (`clean_line`/`clean_block`). Path ids are regex-checked before use. |
| 14 | Info | SQL / PostgREST | Injection. | **Verified**: SQLite uses `?` parameters; f-strings only interpolate fixed column/table constants. PostgREST filters (`eq.`, `in.(…)`) are built from regex-validated ids only. |
| 15 | Info | key hygiene | OpenRouter / Supabase keys. | **Verified**: keys are `SecretStr`; the log formatter redacts `sk-or-…`, `sb_secret_…`, JWT shapes and any field named key/secret/token/authorization; a runtime-built fake key sent through the whole app (probe, 401 with the key echoed by the server, chat) appears in no response and not in `logs/app.jsonl` (`test_key_never_in_responses_or_log_file`). `check_web.py` greps `web/dist` for key shapes → OK. `.env` is git-ignored and untracked; `.env.example` has empty values. The browser never talks to Supabase or OpenRouter (`connect-src 'self'`). |
| 16 | Info | PII in turn logs | Turn logs and stores. | **Verified**: turn logs carry ids, labels and timings only (`turn_log_record` rejects text fields; `test_turn_logs_hold_no_text`); app log lines carry no message or prompt text (prompts are identified by `name:version:hash`; cache keys are hashes, logged truncated). Aliases that look like an email or phone are refused. Scenario attempts store checklist ids and the value label, never the typed text. |
| 17 | Info | unbounded loops | Middleware body read, retries, recovery. | **Verified**: the body loop stops at 32 KB; `LLM_MAX_RETRIES` is capped at 3 and every LLM call has a deadline (≤ 5 s per turn); the LLM re-probe after a failure happens at most once per 60 s (`_maybe_recover`); Supabase calls time out at ≤ 3 s and flip to local. No `while` loop in `app/` besides the bounded body read. |
| 18 | Info | dependencies | Pins. | **Verified**: `requirements.txt` and `requirements-dev.txt` use exact `==` pins for every package (fastapi 0.143.3, uvicorn 0.54.0, pydantic 2.14.1, pydantic-settings 2.16.0, python-dotenv 1.2.4, httpx 0.28.1, numpy 2.4.6, onnxruntime 1.31.0, tokenizers 0.23.3; dev: pytest, respx, ruff, mypy, playwright). `package-lock.json` pins the web build. An offline `pip audit` is not available (it needs the advisory database online); recorded for the integrator. |
| 19 | Info | LLM failure modes | 401/402/429/500/timeout/unreachable/non-JSON/exhausted budget. | **Verified**: every one returns 200 with `mode: "offline"`, the cited K16 answer and a reason in the trace (`trace.agent.fallback_reason` or the verifier reason); an exhausted budget now also says `budget_exhausted` in the trace (API test over `httpx.MockTransport`). |
| 20 | Info | store fallback | `STORE=auto` with wrong Supabase credentials. | **Verified**: unreachable URL (`http://127.0.0.1:9`) and a 401 PostgREST both start on the local store, `/api/health` says `store: "local"` with a probe reason, chat and profiles work, no 5xx, the fake secret appears nowhere. |

## Not changed (outside this task's files)

- `app/agent.py` could set the offline reason itself (finding 19 is done in `app/api.py` for chat and
  scenario feedback; `run_eval.py`, which calls the agent in-process, does not see it).
- Log rotation and a KB row cap (findings 7–8) are small but touch store/logging behaviour during the demo;
  left for after the freeze.
